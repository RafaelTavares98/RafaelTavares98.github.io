Portbill

A warehouse billing pipeline that turns WMS activity logs into auditable invoices. Events are generated, validated, priced through merchant-specific Lua rate cards, and persisted to Postgres as the analytical source of truth. Power BI connects directly to the database.

The Problem

A 3PL warehouse generates thousands of events per day — receive, putaway, pick, pack, ship, return, storage snapshot. Each merchant has a unique contract that turns those events into money: tiered pricing, cold-chain surcharges, grace periods, white-glove fees, CPI adjustments. Pricing rules change often, and codifying them inside the application means every contract amendment becomes a code release.

Portbill solves this the same way real billing systems do: rules live in Lua scripts, one per merchant, hot-loaded at runtime. The pipeline handles generation, validation, persistence, and audit. The pricing math itself is a document the billing team can read and edit directly.

Architecture

Two services, one command. The pipeline seeds a 3-month historical backlog on first start (~1,800 events spread across business hours), then runs an hourly batch using a Poisson distribution proportional to each merchant's monthly volume.

  • Generator: truncated-normal quantities, business-hour timestamps.
  • Validators: five error categories checked per event, in fixed order.
  • Lua runner: a lupa bridge that loads each merchant's rate card with dofile and executes the matching pricing function.
  • Postgres: events, charges, errors, and audit_summary tables, queried directly from Power BI Desktop.

Data Quality as a First-Class Table

A 2% injection rate is applied to every batch, distributed across five error categories: schema mistakes, negative quantities, unknown merchants, duplicate event IDs, and future timestamps. Because injection is deterministic and recorded, the pipeline knows the true number of bad events.

The detection rate (errors_detected / errors_injected × 100) is written once per batch to audit_summary. A run below 100% means a validator regressed — a metric that is on the database, queryable and plottable, not buried in a log.

The Five Merchants

Each contract exercises a different Lua feature and a different real-world billing pattern:

  • NORDVIK-LOGISTICS — three-tier pick pricing.
  • HARLOW-ELECTRONICS — flat per-event fees plus multi-unit surcharge.
  • STONEGATE-APPAREL — pallet grace period and storage overflow break.
  • COASTAL-FRESH — cold-chain and rush multipliers, compounded.
  • ORION-HOMEGOODS — pallet-equivalent pricing plus a white-glove fee.

Stack

Lua 5.4 (via lupa) for pricing rules, Python 3.11 for the pipeline, Postgres 16 for storage, Docker Compose for orchestration, and Oracle Cloud Always Free for deployment. 44 automated tests cover the rate cards, validators, generator, and the Python–Lua bridge.
